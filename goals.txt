# Debt Collection Management System

A professional Arabic RTL **Debt Collection Management System** built with Laravel, designed to manage debtors, collection cases, employees, supervisors, banks, installment companies, assignments, payments, promises, complaints, notifications, reporting, and operational workflows.

The system is being developed as a scalable business platform rather than a simple CRUD application.

---

## Project Status

> **Current Status: Active Development**

The project currently contains a strong operational foundation including database architecture, employee and bank management, collection cases, assignment/distribution, dashboards, settings, notifications, imports, archives, reports, and a professional Arabic RTL interface.

Advanced automation, monitoring, integrations, workflow engines, and some enterprise features are still under development.

# Collection Automation

The long-term goal is to automate collection workflows based on business rules.

For example:

```text
Customer has overdue debt
        │
        ▼
No payment for 3 days
        │
        ▼
Send notification
        │
        ▼
No payment for 7 days
        │
        ▼
Notify supervisor
        │
        ▼
No payment for 15 days
        │
        ▼
Escalate the case
```

# Collection Workflow

The intended collection lifecycle is:

```text
Client
   │
   ▼
Case
   │
   ▼
Debt
   │
   ▼
Assignment
   │
   ▼
Collection Employee
   │
   ├───────────────┐
   ▼               ▼
Call            Promise
   │               │
   ▼               ▼
Follow-up       Payment
                   │
                   ▼
             Confirmation
                   │
                   ▼
                Closed
```

Future automation will extend this lifecycle with:

```text
Overdue
   │
   ▼
Notification
   │
   ▼
Supervisor Escalation
   │
   ▼
SLA Breach
   │
   ▼
Escalation Workflow
```

# Automation Roadmap

The future automation engine will support rules such as:

```text
IF payment_overdue >= 3 days
THEN create notification

IF payment_overdue >= 7 days
THEN notify supervisor

IF payment_overdue >= 15 days
THEN escalate case
```

Future rules may include:

```text
IF promise_broken
THEN notify employee

IF promise_broken repeatedly
THEN notify supervisor

IF case exceeds SLA
THEN escalate

IF employee reaches capacity
THEN stop automatic assignment

IF payment confirmed
THEN update case status
```

# Planned Workflow Engine

The planned workflow engine will allow business rules to be represented as:


This will eventually allow the system to automate collection operations instead of relying entirely on manual actions.

# Important Architecture Principle

The project intentionally separates:

### Implemented Features

Features that already exist and can be used.

### Partial Features

Features where the database, UI, or foundation exists but the complete business workflow still needs implementation.

### Planned Features

Features that are part of the product roadmap but should not be represented as currently available functionality.

This distinction is important for accurate technical documentation, project valuation, client proposals, and production-readiness assessment.

Build a secure, scalable, Arabic-first collection platform capable of managing the complete lifecycle of debt collection operations from:

**Client → Case → Assignment → Collection → Promise → Payment → Confirmation → Closure / Escalation**

while maintaining complete operational visibility, permissions, auditability, automation, and reporting.
